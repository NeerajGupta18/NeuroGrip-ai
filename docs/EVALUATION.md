# NeuroGrip AI - evaluation

Generated by `backend/training/train.py`. Every number in the README comes from this file.

## Data

sEMG for Basic Hand movements (UCI id 313), CC BY 4.0. 5 healthy people each performed 6 everyday grasps 30 times; each recording is 6 s of 2-channel surface EMG at 500 Hz. Recordings are cut into 0.5 s windows every 0.25 s (23 per recording). Chance is 16.7%.

## 2. The same model on a person it has never seen

Leave-one-wearer-out: train on four people, test on the fifth, no calibration.

| Wearer | Single window | Whole recording |
|---|---|---|
| wearer_a | 33.4% | 34.4% |
| wearer_b | 20.3% | 19.4% |
| wearer_c | 43.5% | 44.4% |
| wearer_d | 25.4% | 27.8% |
| wearer_e | 19.5% | 21.7% |
| **mean** | **28.4%** | **29.5%** |

This is the central finding: accuracy collapses from 95.1% to 29.5%, barely above the 16.7% chance level. With two electrodes, where each grasp sits in feature space depends on the person's anatomy and electrode placement. A bionic hand cannot ship with one fixed model; it has to be calibrated to its wearer.

## 3. Calibration recovers it

The wearer performs each grasp a few times. Only the class means are re-estimated (`personalised_means` in `model.py`); the covariance learned from other people is kept. Scored on that wearer's remaining recordings, averaged over 20 random choices of calibration recordings.

| Calibration recordings per grasp | Whole-recording accuracy |
|---|---|
| 0 | 29.5% |
| 1 | 84.8% |
| 2 | 89.7% |
| 3 | 91.7% |
| 5 | 93.7% |
| 10 | 94.2% |

How strongly should other people's class means be trusted? Prior strength is measured in windows; one recording is 23 windows.

| Prior strength (windows) | 1 rep | 3 reps | 10 reps |
|---|---|---|---|
| 0.5 | 84.5% | 92.0% | 94.6% |
| 5.0 (deployed) | 82.8% | 92.5% | 93.9% |
| 50.0 | 52.5% | 74.7% | 91.0% |
| 250.0 | 34.9% | 45.5% | 67.9% |

A weak prior wins: what transfers between people is the covariance (the distance metric), not the class means.

## 4. Day-to-day drift

Database 2: one person recorded on three consecutive days (electrodes re-applied each day). Model trained on day 1.

| Test day | No recalibration | 3 reps/grasp | 10 reps/grasp |
|---|---|---|---|
| Day 1 (held-out recordings) | 78.3% | - | - |
| Day 2 | 44.3% | 70.8% | 70.2% |
| Day 3 | 43.3% | 66.5% | 67.0% |

Re-applying the electrodes shifts the signal enough to roughly halve accuracy, and a short recalibration only partly restores it. This person's recordings are also harder than Database 1 even on the same day. Daily drift is an open problem for this approach, not a solved one.

## 5. Confidence and abstention

After 3 calibration recordings per grasp. Window scores are averaged and multiplied by one fitted number, the evidence scale (see `predict` in `model.py`), before the softmax. For each wearer it is fitted on the other four: wearer_a 5.75, wearer_b 4.5, wearer_c 5.5, wearer_d 4.75, wearer_e 4.75 (a recording has 23 overlapping windows). The agent refuses to act below a confidence floor.

| Confidence floor | Recordings acted on | Accuracy when acting |
|---|---|---|
| 0.0 | 100.0% | 91.1% |
| 0.5 | 98.2% | 91.9% |
| 0.6 | 92.7% | 94.0% |
| 0.7 | 86.7% | 95.6% |
| 0.8 | 79.2% | 96.9% |
| 0.9 | 68.4% | 98.1% |

## 6. Safety gate

False alarms on real clean recordings: **1 of 900 (0.1%)**, with thresholds set from the other four wearers.

| Injected fault | Detected |
|---|---|
| dropout | 100.0% |
| spike | 100.0% |
| hum | 100.0% |

Thresholds for each wearer are set from the other four wearers only. Faults are synthetic; detection rates are a sanity check, the false-alarm rate is the real test.

## 7. Why not a bigger model?

Single-window accuracy, same splits.

| Model | Trained on the wearer | Unseen wearer |
|---|---|---|
| Logistic regression | 88.3% | 26.4% |
| SVM (RBF) | 91.1% | 26.3% |
| Random forest | 89.6% | 26.4% |
| Gaussian shared-covariance (deployed) | 85.4% | 28.4% |

More flexible models gain a few points within a wearer and nothing on an unseen wearer. The bottleneck is the difference between people, not model capacity, so the deployed model is the one that can be personalised from a handful of recordings and explained exactly.

## Latency

1.33 ms to featurise and classify one 6 s recording (single CPU core, NumPy).

## Limits

- Five healthy wearers, two electrodes, six grasps. Small by any standard.
- Recordings are replayed, not streamed from hardware. No amputee data.
- Calibration here uses correctly labelled recordings; a real fitting session has label noise.
- Sensor faults are synthetic.
